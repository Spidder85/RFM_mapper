# RFM Automation

RFM Automation - консольная система на Java 21 для получения обновлений перечней Росфинмониторинга, их обработки в Zenith, подготовки черновиков ФЭС и отправки служебных уведомлений.

Программа предназначена для автоматического запуска через Планировщик заданий Windows, обычно раз в час. ФЭС в Росфинмониторинг автоматически не отправляются: сотрудник проверяет подготовленный черновик и принимает решение вручную.

## Возможности

- Получение перечней через API сервисного концентратора Росфинмониторинга.
- Работа с перечнями террористов и экстремистов, ООН и МВК.
- Подключение с клиентским сертификатом, включая CryptoPro CSP/JCP/JTLS.
- Обмен между серверами через файловые события.
- Загрузка обновленных перечней в Zenith.
- Массовая проверка Zenith, выгрузка и анализ XLSX-отчетов.
- Поиск новых совпадений и подготовка черновиков ФЭС.
- Понятные уведомления по email и Telegram.
- Повтор временно неуспешных операций Zenith и сохранение постоянных ошибок для разбора.

## Архитектура

Рекомендуемая рабочая схема состоит из трех независимых этапов:

```text
Сервер 1                         Сервер 2                         Сервер 3
--------                         --------                         --------
rfm-downloader                   zenith-processor                 zenith-processor
только скачивание                IMPORT_ONLY                       CHECK_ONLY

RegistryUpdated событие  ----->  загрузка в Zenith  ----------->  массовая проверка
                                 ImportCompleted событие           отчет / анализ / черновики ФЭС
                                 уведомление об импорте             уведомление о проверке
```

Режим `FULL` сохранен для односерверного варианта. В трехсерверной схеме третий сервер обязан работать в `CHECK_ONLY`, иначе он повторно импортирует уже загруженный перечень.

## Модули

| Модуль | Назначение |
| --- | --- |
| `common` | Общие JSON-утилиты, очереди событий, retry/retention, summary обработки и контракты уведомлений. |
| `rfm-downloader` | Авторизация в Росфинмониторинге, проверка версии, скачивание, распаковка, audit и публикация `RegistryUpdated`. |
| `zenith-processor` | Импорт в Zenith, массовая проверка, отчеты, анализ, черновики ФЭС и уведомления. |
| `distribution` | Сборка установочного ZIP с приложениями, зависимостями, скриптами и рабочими конфигами. |

## Режимы Zenith

| Режим | Назначение |
| --- | --- |
| `FULL` | Импорт, публикация офисных событий, проверка, отчет и черновики ФЭС. |
| `IMPORT_ONLY` | Только загрузка нового перечня в Zenith и создание событий для серверов проверки. |
| `CHECK_ONLY` | Только проверка по `ZenithImportCompleted`, отчет, анализ и черновики ФЭС. |

Доступны способы запуска `--once`, `--drain`, `--watch`. Для запуска по расписанию используйте `--drain`: он обрабатывает все доступные события одной партией.

## События и повторные попытки

```text
new -> processing -> processed
                  -> retry  -> new
                  -> failed
```

- Временная недоступность Zenith, timeout и повторяемые ответы API переводят событие в `retry`.
- Некорректные и неповторяемые ошибки переводят событие в `failed`.
- Перед обработкой остается только последнее ожидающее событие каждого перечня; более старые ожидающие события того же перечня удаляются.
- Завершенные events и summary хранятся 30 дней. `new`, `processing`, `retry` автоматически не удаляются.

## Уведомления

Уведомления необязательны и по умолчанию выключены.

- `IMPORT_ONLY` отправляет одно итоговое сообщение о загруженных в Zenith перечнях.
- `CHECK_ONLY` и `FULL` отправляют одно итоговое сообщение о результатах проверки, найденных лицах и черновиках ФЭС.
- `Email.ImportTo` необязателен: при его наличии уведомление импорта получают все офисы; при отсутствии используется обычный `Email.To`.
- Telegram использует настроенные `ChatIds` для каждого включенного уведомления Zenith.
- Если RFM запускает Zenith сам, уведомление Zenith можно подавить, чтобы ушло только одно общее сообщение.

## Конфигурация

Рабочие конфиги располагаются рядом с исполняемыми скриптами:

```text
config/config.json
config/zenith-config.json
```

Поддерживаемые переменные окружения:

```text
RFM_USERNAME
RFM_PASSWORD
RFM_CERT_SERIAL
ZENITH_PASSWORD
```

Не храните в Git реальные логины, пароли, токены, сертификаты, перечни, отчеты, логи и черновики ФЭС.

В `Zenith.BaseUrl` указывается только адрес сервера:

```json
"BaseUrl": "https://zenith-server"
```

Путь `/zenith-object/api/...` приложение добавляет самостоятельно.

## Хранение данных

```text
downloads/zenith-reports/   XLSX-отчеты Zenith, бессрочно
downloads/fes-packages/     Черновики ФЭС, бессрочно
events/.../processed/       Завершенные события, 30 дней
events/.../failed/          Ошибочные события, 30 дней
events/.../results/         Summary обработки, 30 дней
logs/                       Архивы логов, 30 дней
```

Чтобы бессрочно хранить загруженные перечни Росфинмониторинга, установить:

```json
"KeepDownloadedVersions": 0
```

Положительное значение включает ограничение числа версий. Срок хранения audit задается отдельно через `KeepAuditDays`.

## Сборка и дистрибутив

Сборка из корня Maven-проекта:

```bat
mvn clean package
```

Установочный ZIP создается здесь:

```text
target/distr/rfm-automation-<version>.zip
```

В архив входят JAR-файлы, зависимости, скрипты запуска и рабочие конфиги.

## Скрипты запуска

| Скрипт | Назначение |
| --- | --- |
| `run-rfm.bat` | Запуск этапа скачивания RFM. |
| `run-zenith-once.bat` | Обработка одного события Zenith. |
| `run-zenith-drain.bat` | Обработка всех доступных событий Zenith. |
| `run-zenith-watch.bat` | Постоянное наблюдение за очередью Zenith. |

Пример запуска трех этапов:

```bat
run-rfm.bat
run-zenith-drain.bat --mode IMPORT_ONLY
run-zenith-drain.bat --mode CHECK_ONLY
```

## Эксплуатационные рекомендации

- Не запускайте одновременно два экземпляра, работающих с одной очередью.
- У учетных записей Планировщика заданий должен быть доступ к сетевым папкам events.
- Папки `config`, `downloads`, `events`, `data`, `logs` должны находиться на постоянном диске.
- При проблемах проверяйте `failed`, `retry` и журналы Zenith.
- Перед будущей отправкой ФЭС всегда вручную проверяйте сформированные черновики.
